Offline Music Player — iOS UI reference

Static, annotated screens for implementation in native SwiftUI. Target: iPod touch 7th gen, iOS 15, 320 × 568 pt, portrait. Generated 2026-10-12.

Read this first (for Codex / other agents).
  • This is a design reference, not app code. Do not embed it in a web view or port its HTML/CSS/JS. Reimplement each screen with SwiftUI/UIKit using the mappings below.
  • Precedence: the engineering spec (v1.0) wins over this document wherever they differ. Conflicts, gaps and decisions are listed in “Reconciliation with the engineering spec”.
  • All data is placeholder: catalog, counts, artwork, lyrics, scan numbers and statistics are invented. Never ship sample data; bind to the real Core Data model.
  • Machine-readable copy: tokens, metrics, symbols, components, screens, navigation edges and conflicts are in <script type="application/json" id="design-spec"> at the bottom of this file. Each screen section has id="screen-…" and data-screen-id.
  • Interaction hints in markup: inside frames, data-a="action|arg|arg" marks tap intent (e.g. push|album|a1, play|album:a1|a1-2, np). They document navigation only; they are not an API.
  • Unverified: nothing here proves iOS 15 runtime behavior, API availability or device performance.

Screen 1 — First launch / empty library

SwiftUI mapping
NavigationView › empty-state VStack (Image(systemName:"folder.badge.plus") 64–72 pt, Text title2 bold, Text subheadline secondary, Button(.borderedProminent) “Add Music Folder”, Label footnote “Your music stays on your device.”). .navigationTitle("Library"), large display mode. Shown only when MusicSource count == 0.
Data
MusicSource: count == 0. No other fetches.
States
empty (this frame). Tab bar and other tabs remain usable; Playlists/Search show their own empty states.
Actions / navigation
“Add Music Folder” → presents UIDocumentPickerViewController (system UI, not styleable) → on success persist security-scoped bookmark → create MusicSource → present Scan sheet (screen 15).
Notes
No account, login or subscription UI. No mini-player (no current track).

320 × 568 pt · 03-songs

Screen 3 — All Songs

SwiftUI mapping
List(.plain) + search (.searchable or in-list field as drawn). Header rows: count + Menu for sort, then two Buttons (Play / Shuffle, .bordered). Row = HStack { artwork 40×40, VStack(title callout, artist footnote secondary), Spacer, Menu(ellipsis) }. Load thumbnails asynchronously from ArtworkCache.
Data
Track sorted by title (default), artist, album or dateAdded. Count = fetch count. The prototype shows a 38-song sample while the header says “1,434 Songs” (placeholder).
States
populated; filtered (search); current track highlighted (accent-colored title); unavailable rows (see S1).
Actions / navigation
Row tap → PlaybackCoordinator.play(queue: songs in current order, startAt: track); mini-player appears; Now Playing opens from the mini-player. Ellipsis → context menu. Swipe left → Play Next (.swipeActions, iOS 15).
Notes
Tapping a song does NOT auto-open Now Playing (matches Apple Music). Row height 52 pt.

320 × 568 pt · 08-now-playing

Screen 8 — Now Playing

SwiftUI mapping
Present with .fullScreenCover (full height is needed at 568 pt; an iOS 15 .sheet is card-style). VStack: header (dismiss chevron.down, “NOW PLAYING” caption2 + context name footnote semibold, ellipsis Menu); artwork region fills remaining height, square, max 240 pt (shrink to 88% when paused); title + artist; favorite button; seek bar; elapsed/remaining labels; transport row (backward.fill, play/pause 46 pt, forward.fill); secondary row (shuffle, repeat/repeat.1, quote.bubble, list.bullet).
Data
PlaybackCoordinator (single instance): currentTrack, elapsed, duration, isPlaying, shuffle, repeat (off/all/one), queue. Views observe; they never own an engine.
States
playing; paused (artwork scaled 0.88, shown here); no lyrics (button still present); unavailable-track error (S3).
Actions / navigation
Lyrics button → lyrics mode (09). Queue button → Up Next (08b). Dismiss → previous screen. Seek drag → coordinator.seek.
Notes
All controls fit in 320×568 without clipping. No volume slider (hardware buttons). Drive elapsed time from the engine’s time observer; keep timers off while paused.

Screen 9 — Synchronized lyrics

SwiftUI mapping
ScrollViewReader + ScrollView { LazyVStack } of lines; current line primary color, others ≈32% opacity; scrollTo(currentIndex, anchor: UnitPoint(x:0.5,y:0.32)); tap line → coordinator.seek(to: line.time). Manual scroll should pause auto-follow briefly. Controls below are the same as Now Playing.
Data
LyricsService returns [LyricLine(time: TimeInterval?, text)] from embedded tags or an adjacent .lrc (spec §8). The current line is derived from audio playback time, including seeks and pauses.
States
synced (this frame); plain (09b); unavailable (09c).
Actions / navigation
Tap line → seek. ✕ or compact header → back to artwork mode.
Notes
Lyric text here is invented placeholder text. Restrained animation only.
